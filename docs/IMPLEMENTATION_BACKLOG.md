## Assignment template

```text
Task ID and objective:
Implementation agent: gpt-6-luna / max
Assigned branch (`work/<ID>-slug`) and dedicated worktree path:
Allowed paths:
Read first / relevant requirement IDs:
Inputs and required dependency outputs:
Interface/schema version and forbidden boundary changes:
Acceptance scenarios:
Verification commands and allowed external calls/budget:
Escalate to root if:
Handoff: branch, commit SHA(s) and exact messages; changed files, behavior, actual results, limitations, migrations/configuration.
```

The root resolves shared interfaces before dispatch and reviews the task branch diff plus verification evidence after handoff. Every implementation subagent uses a separate branch/worktree and commits each coherent work package with a descriptive message. Root integrates only after review. Earlier SPEC-01/02/03 drafts were the one-time shared-checkout exception documented in [DELIVERY_LOG.md](DELIVERY_LOG.md); those agents hit usage limits before producing branch commits. Do not create fictional agent commits or attribute later root changes to them. Split large packages into bounded subtasks without losing parent requirement links. Use WSL for all local runtime verification. No paid provider, cloud project or live connector is included without a separately scoped authorization.

Live integration, UI scaffolding against fixtures and backend policy may progress independently where contracts permit. Do not parallelize edits to the same migration, lockfile or contract without an explicit owner.

OBS-01 is a continuing integration package: each task implements its own telemetry immediately, so nobody waits for a late monitoring task to add trace IDs. EVAL-01 supplies human-adjudicated cases for model evaluation, publication-quality thresholds, and quality claims. Task-local synthetic fixtures may test deterministic parsers and edge cases, but they do not replace EVAL-01 or justify claims about source accuracy. Public-facing UI can begin with reviewed contract fixtures while API implementation is in progress; final acceptance still requires the real API.

SPEC-03 wireframes began while SPEC-02 was in progress; root review records their design baseline as accepted and aligns the OpenAPI projection to schema 2.0. BOOT-01 is accepted as a local synthetic context/list shell; it does not imply a complete API or waive implementation dependencies. UI-00 is accepted as a fixture-backed screen slice, not a finished or live product surface; its branch, review, and limitations are recorded in [the assignment](assignments/UI-00.md). PLATFORM-01 is accepted as a no-provisioning compatibility report: bounded demo fit is plausible from published ceilings, but provider performance and extension activation are unverified, and the 30-day off-provider backup gate still blocks live-source persistence. DATA-01 is accepted as a local persistence foundation, with Worker integration and provider compatibility still unverified; it does not enable live persistence. DATA-02-CORE is accepted as synthetic local text/chunk processing; contact matching is incomplete and hosted/concurrent database behavior remains unverified. RAG-CORE is assigned as the next local task. User interviews and human-adjudicated evaluation labels remain required and are not supplied by agent review. Root periodically pushes reviewed, integrated checkpoints to the connected origin; implementation agents commit on their task branches and do not push.
